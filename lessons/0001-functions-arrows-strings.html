Functions, Arrows and Strings

Two pieces of JavaScript syntax, both of which are new spellings of things you already write in Perl. No Vue, no tooling, no build step. About 20 minutes.

I'm your teacher for this. If a bit doesn't land, say so — including "this is still pitched too high". That feedback is more useful to me than you struggling through. Ask anything.

The win

By the end you'll be able to read (n) => n * 2 without stopping, and know when JavaScript needs backticks instead of quotes. These two show up in nearly every line of the code you'll write later.

Part 1: Functions

Start from what you know. Here's a named function in both languages:

Perl

sub double {
    my ($n) = @_;
    return $n * 2;
}

print double(5);   # 10

JavaScript

function double(n) {
  return n * 2
}

console.log(double(5))   // 10

Same idea. The differences are cosmetic: parameters are named in the signature instead of unpacked from @_, no sigils on variables, and semicolons are optional in JavaScript (most modern codebases omit them).

Anonymous functions — you already use these

In Perl you can store a function in a variable — a coderef:

Perl

my $double = sub {
    my ($n) = @_;
    return $n * 2;
};

print $double->(5);   # 10

JavaScript can do exactly this, and the older syntax looks almost identical:

const double = function (n) {
  return n * 2
}

console.log(double(5))   // 10

Note there's no -> needed to call it — just double(5).

The arrow function is shorthand for that

An arrow function is an anonymous function with shorter syntax. That is the entire idea. It is Perl's sub { ... } with the word function removed and a => inserted:

const double = function (n) { return n * 2 }   // anonymous function
const double = (n) => { return n * 2 }         // same thing, arrow syntax

Read => out loud as "goes to": n goes to n times 2. Parameters on the left, body on the right.

The short form

When the body is just a single expression being returned, you can drop the braces and the word return:

const double = (n) => { return n * 2 }   // long form
const double = (n) => n * 2              // short form — identical behaviour
The one that catches people

Braces mean "here comes a block of statements, and I'll return explicitly". No braces means "this single expression is the return value".

So (n) => { n * 2 } — braces but no return — is a function that computes n * 2, throws it away, and returns nothing. It's a common typo and it fails silently.

Two more shorthand rules you'll see in real code:

n => n * 2           // single parameter: parentheses optional
() => 'hello'        // no parameters: empty parentheses required

Part 2: Template literals

You had this almost exactly right. In Perl, double quotes interpolate:

Perl

my $name = "Michelle";
print "Hello, $name";      # Hello, Michelle

JavaScript needs backticks — the key above Tab — and wraps the variable in ${ }:

JavaScript

const name = 'Michelle'
console.log(`Hello, ${name}`)      // Hello, Michelle

Your ${sample} guess was correct. The piece to add is that it only works inside backticks.

Perl habit that will bite you

Ordinary quotes in JavaScript never interpolate. Both of these print the literal text rather than the value:

console.log("Hello, ${name}")   // Hello, ${name}
console.log('Hello, ${name}')   // Hello, ${name}

There is no JavaScript equivalent of the single/double quote distinction you know from Perl — ' and " behave identically. Interpolation is a backtick thing.

What backticks buy you over Perl

${ } takes any expression, not just a variable name — arithmetic, a function call, anything that produces a value:

const miles = 6.2
console.log(`That's ${(miles * 1.609).toFixed(1)} km`)   // That's 10.0 km
console.log(`Doubled: ${double(21)}`)                     // Doubled: 42

They also span multiple lines without any escaping:

const report = `Distance: ${miles} miles
Weather: clear`

Your turn — 10 minutes, in a scratch file

You have Node installed (npm came with it), so you can run plain JavaScript from the terminal — no build step, no browser.

  1. Make a folder scratch/ in the project and create scratch/01-functions.js.
  2. Write double three ways: as a function declaration, as an arrow with braces and return, and as a short-form arrow. Log all three results to prove they match.
  3. Write const paceLabel = ... as an arrow function taking minutes and miles, returning a sentence via a template literal — something like "6.2 miles at 9.7 min/mile". Do the division inside the ${ }.
  4. Deliberately break one: write an arrow with braces but no return, log it, and see undefined with your own eyes. Then fix it.
  5. Run it: node scratch/01-functions.js
Tip

If you'd rather experiment line by line, type node on its own for an interactive prompt — like perl -de1, but friendlier. .exit quits.
