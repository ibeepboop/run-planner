Your First Typed Fetch

Call the Open-Meteo geocoding API when a component mounts, type what comes back honestly, and render it. About 25 minutes.

I'm your teacher for this. If any part of this is unclear, or you want to go deeper on something, just ask in the session — that's what I'm here for. Don't grind on a confusing bit alone.

The win

By the end you'll have a Vue component that, on load, searches for "Boulder" and renders both Boulders — Colorado and Montana — with enough detail to tell them apart. Hardcoded query, no input box yet. One thing at a time.

Knowledge: three ideas

1. ref() is a box that Vue watches

In Vue, a plain variable is invisible to the template — reassign it and nothing re-renders. ref() wraps a value in a reactive box (a "reference" Vue tracks). When the contents change, anything displaying it updates.

import { ref } from 'vue'

const count = ref(0)   // Ref<number>, inferred
count.value++          // in script: use .value

The rule that trips everyone up: in <script> you write .value; in <template> you don't. Vue unwraps refs automatically in templates. So count.value++ in script, but {{ count }} in the template.

When a ref starts empty but will hold something later, TypeScript can't infer the type — give it an explicit type parameter:

const places = ref<GeocodingResult[]>([])
const error  = ref<string | null>(null)

Vue docs — Reactivity Fundamentals

2. onMounted() is "the component is now on screen"

A lifecycle hook — a function Vue calls at a specific moment in a component's life. onMounted fires once, after the component is inserted into the page. It's where first-load data fetching goes.

import { onMounted } from 'vue'

onMounted(async () => {
  // fetch here
})
Why not just await at the top?

Top-level await in <script setup> works, but it turns your component into an async component that needs a <Suspense> wrapper to render. That's a bigger concept than you need today. onMounted keeps the component ordinary.

3. fetch only rejects on network failure

This surprises people coming from other HTTP libraries. A 404 or 500 is a successful fetch as far as the promise is concerned — the server answered. The promise only rejects if the request never completed (DNS failure, offline, CORS block).

So you must check response.ok yourself:

const response = await fetch(url)
if (!response.ok) {
  throw new Error(`Geocoding failed: ${response.status}`)
}
const data = await response.json()   // note: typed as `any`

The honest type

Here's the real response for a search with no matches, taken live from the API:

{"generationtime_ms": 0.69}

No results key at all. Not [], not null — absent. If you type it as results: GeocodingResult[] then data.results.map(...) compiles perfectly and crashes at runtime the first time someone searches for a typo.

Type what the API actually returns:

interface GeocodingResult {
  id: number
  name: string
  latitude: number
  longitude: number
  country?: string    // optional in the API
  admin1?: string     // state/region — often absent
}

interface GeocodingResponse {
  results?: GeocodingResult[]   // ← absent when nothing matches
}
The boundary rule

response.json() returns any. TypeScript will let you assert it into any shape you like and will never check you were right — the compiler has no idea what a server sent. Types at an API boundary are a claim, not a guarantee. Which is exactly why the claim should match reality, and why the optional ? above matters so much.

Your turn to build

  1. Delete src/components/HelloWorld.vue and empty out src/App.vue. Clear the scaffold noise.
  2. Create src/types.ts with the two interfaces above.
  3. Create src/components/PlaceSearch.vue using <script setup lang="ts">. It should hold two refs: one for the results array, one for an error message that starts null.
  4. In onMounted, fetch https://geocoding-api.open-meteo.com/v1/search?name=Boulder&count=5&language=en&format=json. Check response.ok. Wrap it in try/catch and put any error message into your error ref.
  5. Render the results with v-for — show name, admin1 and country so the two Boulders are distinguishable. Remember :key="place.id".
  6. Handle the empty case in the template: if there are no results, say so rather than rendering nothing.
  7. Use PlaceSearch in App.vue, then run npm run dev.
Stuck?

Two things worth trying before asking: open the network tab and confirm the request actually goes out, and console.log the parsed JSON before you touch .results. Most first-fetch bugs are one of those two places. Then ask me — bring the error text.
